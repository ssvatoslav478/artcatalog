# Каталог рисунков

Бот конкурсу школи «Палітра»: `/start` → контакт → код сервісу верифікації → малюнки.
Теми групи: **91** — старт, **93** — контакт, **95** — код і ручна перевірка.

На карточке один рисунок, имя, возраст, школа, город, сведения об участнике и работе.
«Следующий участник» заменяет фото и подпись в том же сообщении.
«Выбрать» сохраняет участника для текущего менеджера и добавляет кнопку завершения.
Можно выбрать несколько работ. Выборы разных менеджеров независимы.
Повторное нажатие не создаёт дубликат. Завершение и повторный просмотр не сбрасывают выбор.
После перезапуска бота все текущие заявки и выборы очищаются.

## Запуск

Нужен Python 3.11 или новее. Откройте терминал в этой папке:

```console
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

На Linux используйте `.venv/bin/python` вместо `.venv\Scripts\python`.
Скопируйте `.env.example` в `.env`. Укажите токен нового бота от BotFather,
ID закрытой супергруппы и Telegram ID менеджеров через запятую.
Добавьте бота в группу с включёнными темами, разрешите отправку сообщений.
В группе должны существовать темы 91, 93 и 95: это ID тем, а не их названия.
Запускайте только один экземпляр бота на эту базу данных.

Запустите проверку каталога и бота:

```console
.venv\Scripts\python admin.py check
.venv\Scripts\python bot.py
```

После контакта пользователь вводит код, полученный от вашего сервиса верификации.
Бот отправляет его в тему 95 с кнопками «Код верный» и «Код неверный».
Кнопки доступны только ID из `MANAGER_IDS`. При одобрении открывается `/catalog`,
при отклонении пользователь вводит код заново. Пока заявка ожидает решения,
повторный ввод не принимается. Для отзыва доступа удалите ID из `MANAGER_IDS` и перезапустите бота.

## Реальные участники

Каталог поставляется пустым: исходный архив не содержал анкет и рисунков.
Добавьте настоящие работы, предоставленные для конкурса, в папку `images`,
а данные — в `participants.json`. Не выдавайте сторонние работы за заявки в конкурс.
Если сведения неизвестны, укажите «Не указано». Пример структуры ниже — шаблон,
не реальная анкета; замените все поля до загрузки:

```json
[
  {
    "id": 1,
    "name": "Имя из анкеты",
    "age": "Возраст из анкеты",
    "school": "Учебное заведение из анкеты",
    "city": "Город из анкеты",
    "about": "Краткая информация из анкеты",
    "title": "Название рисунка",
    "description": "Описание работы участником",
    "image": "images/001.jpg",
    "source": "Источник и сведения о разрешении на использование"
  }
]
```

Рисунок — локальный JPG/PNG до 10 MB, удовлетворяющий требованиям Telegram к фото.
Держите подпись короткой (проверка ограничивает её 1000 единицами UTF-16 с разметкой).
Путь к рисунку должен быть внутри папки бота. ID уникальны и постоянны:
не присваивайте ID старой работы другому участнику. Просмотр идёт по возрастанию ID.
После изменения каталога проверьте его командой `admin.py check` и перезапустите бота.
Текущий просмотр начинает следующий рисунок по ID, а `/catalog` начинает с первого.

## Данные и проверка

Бот не использует базу данных и не создаёт файлов с кодами, контактами или выборами.
Всё рабочее состояние существует только до перезапуска процесса. Номера телефонов
отправляются в тему 93; доступ и сроки хранения сообщений этой группы задаёт организатор.
Если контакт не удалось доставить в группу, бот предлагает повторить отправку.
Ошибки отправки остальных событий фиксируются в журнале процесса без секретов;
автоматической повторной доставки этих событий нет.

Тесты: `python -m unittest discover -s tests -v`.
Для проверки в Telegram: войдите менеджером, отправьте свой контакт, введите
выданный код, выберите работу, перейдите дальше, завершите и перезапустите бот.
Проверьте события во всех трёх темах и выбор участника до перезапуска бота.
Неавторизованный аккаунт не должен получать доступ к анкетам.

API изображений сверено с документацией aiogram:
https://docs.aiogram.dev/en/v3.22.0/api/types/input_media_photo.html
